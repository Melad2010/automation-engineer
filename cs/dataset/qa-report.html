6. Link health

Method: one HEAD request per website with a 10 s timeout (for connecting and for each read). If HEAD failed or returned a 4xx/5xx code (405 included), a GET request followed. Redirects were followed by hand, up to 10 hops, so every hop counted against the limit of 1 request per second across the whole run. User-Agent: "portfolio-sample/1.0 (data quality demo; website link check)". Websites that timed out were checked again once after the full pass. Certificate failures got one extra GET with relaxed TLS settings, as a diagnostic only; it does not change the result.

Network note. Before the check, two plain-HTTP canary requests (example.com and example.org, which normally answer 200) were redirected to an unrelated page. Plain-HTTP traffic was being intercepted on the checking network, so a plain-HTTP answer would have come from the network, not from the website. Every http:// address, and every http:// redirect hop, was therefore requested over https:// with the same host, path and query. 123 of the 231 checked addresses start with http://. A site that could only be tested over plain HTTP is reported as unverified, not as dead. A domain that does not resolve fails the same way on both schemes, so it is still reported as not resolving. Canary results: http://example.com/: HTTP 307 redirect to an unrelated site; http://example.org/: HTTP 307 redirect to an unrelated site.

A 401, 403 or 429 answer means the server is online but refused an automated request. These sites were not opened in a browser, so they are reported as unverified, not as dead.

Three rules sit on top of the raw status. Each affected row names its rule in the outcome_rule column of QA_Audit, and the raw code stays in website_status.

  1. A 405 or 406 answer to the GET request usually comes from a request filter, so it is grouped with refused (2 rows).
  2. When the https:// stand-in for an http:// address was answered directly with an error, the plain-HTTP site itself was not tested, so the row is unverified (2 rows). When the site redirected first and the target then failed, the failure stands.
  3. A 2xx or 3xx answer that lands on a domain sharing no word or initials with the company name is not counted as live (4 rows). The address may have lapsed, or the firm may have been bought; either way the link does not reach a site that can be tied to the company. Their pages were not opened.

10. Limits

  • Wikidata is edited by volunteers. It covers notable companies, not every UK firm, and a company without an industry code (P452) cannot match the filter.
  • Industry codes are Wikidata's own. Some fit loosely; section 9 flags the clearest cases.
  • A live website shows the address works today. It does not prove the company still trades.
  • Only the listed home page was requested, once per check. No pages were crawled and no content was read.
  • Plain HTTP could not be tested from the checking network (section 6). Sites that work only over plain HTTP are marked unverified; a re-run from another network would settle them.
  • Results can change: the query service can lag live Wikidata by minutes, and websites change daily.

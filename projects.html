Configurable quote generator

Excel formulas, VBA, Apps Script, Python50 tests

One catalogue, one set of pricing rules, four implementations — because clients live in Excel, in Google Sheets, and in scripts. Quantity breaks, customer tiers and manual discounts, all capped by a margin floor that says what it refused.

  • Product, option and tier dropdowns; quantity validation that refuses 0 and 2.5 at entry
  • Pricing logic on protected sheets; cost and margin off the printed customer copy
  • A small Excel formula evaluator runs the generated workbook in CI, so the sheet and the engine cannot drift apart
What the tests caughtThe engine rounded the margin-floor cap to two decimals and the sheet did not. Rounding a cap up pushes the line back under the very floor it exists to protect — about 19 cents on a $4,200 pump, on exactly the high-volume orders where margin is thinnest. The cap now keeps full precision and only the printed note rounds.

Excel KPI dashboard from a CSV

Python, openpyxl, Excel formulas45 tests

Six KPI cards, a month selector and three charts, all of them formulas over the data rather than pasted values. Refreshing next month is: paste the new rows, pick the month.

  • A row that cannot be parsed is quarantined on its own sheet with the line number and the reason — never counted as zero
  • A previous period of zero shows blank, not +100% or infinity
  • The tests execute the workbook's own SUMIFS and card formulas and compare them against the Python engine, month by month
What the tests caughtMargin % was rounded to two decimals before the month-over-month change was taken, while the sheet computed it from the full-precision ratio. The two disagreed by a few hundredths of a point every single month. The engine now keeps the ratio unrounded and only the display rounds.

Lead qualification agent, with the guardrails on

Python, Anthropic API, Claude Opus 571 tests

An agent that researches an organisation with tools and returns a schema-validated verdict. The interesting part is not that it calls a model — it is what makes it stop.

  • Cost, token and request budgets, each stopping the run rather than warning about it
  • A token reserve for the reply that has not arrived yet, so the last request cannot sail past the ceiling
  • Sliding-window rate limit, tool allowlist, per-tool call caps, oversized results truncated
  • Retries 429 and 5xx, never retries a 400; a refusal arrives as HTTP 200 and is checked before any content is read
  • Tools that return found: false rather than inventing a record, and a score that is computed, not estimated

What runs through all four

The same three habits, from twelve years of medical-device engineering where a device that fails quietly is the worst kind.

Report the gaps, do not fill them

A missing field is listed, not guessed. An unparseable row is quarantined, not counted as zero. A number you cannot trace is worse than one that is missing, because it looks like a fact.

Test the deliverable, not a model of it

The spreadsheets ship as workbooks, so the tests execute the workbooks' own formulas and compare them against the code. Both bugs above were found that way.

Make the failure path the default case

Backoff that refuses to retry a 404. Budgets that stop a run. Validation that names the invalid value. Most of the test effort goes here, because most of the real trouble does.
